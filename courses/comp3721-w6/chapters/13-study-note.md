## Lecture 06a: bandwidth utilization and multiplexing

- **Bandwidth utilization**: the wise use of available bandwidth (links have limited bandwidths). Two techniques: **multiplexing**, goal **efficiency**, combine several channels into one; **spectrum spreading**, goal **privacy**, not discussed.
- **Multiplexing**: the set of techniques that allow the simultaneous transmission of multiple signals across a single data link. Possible whenever the bandwidth of the medium is greater than the bandwidth needs of the devices (optical fibre has far more than needed).
- Figure: n input lines → **MUX** → **1 link, n channels** → **DEMUX** → n output lines. **Link** = the physical path. **Channel** = the portion of a link.
- Highway analogy: vehicles = signals, multi-lane highway = the transmission channel; TDM = vehicles get time slots to enter, FDM = each lane dedicated to a type of vehicle.

| Technique | Signals | What is shared | How |
|---|---|---|---|
| FDM, Frequency-Division | analog | bandwidth: a carrier frequency per channel | modulator per source, + into one composite signal; filter + demodulator at the receiver |
| WDM, Wavelength-Division | analog, optical | wavelengths (very high frequencies) on one fibre | a prism combines and splits the light sources |
| TDM, Time-Division | digital | time: one slot per input in each frame | MUX interleaves units, DEMUX separates slots, framing bits keep them in step |

- **FDM**: analog signals generated by each sending device modulate different carrier frequencies; the modulated signals are combined into a single composite signal. Each channel corresponds to a specific carrier frequency allocated to an individual signal source. Condition: link bandwidth (in hertz) greater than the combined bandwidths of the signals.
- **Guard bands**: strips of unused bandwidth that separate channels from each other, to prevent signals from overlapping and interference. n channels → **n − 1** guard bands.
- FDM applications: telephone companies, AM and FM radio broadcasting, television broadcasting. Often no physical MUX: stations agree on different carrier frequencies; a cellular base station assigns a carrier to a user and reassigns it when the user hangs up.
- Slide example: three 4 kHz voice channels, link 12 kHz from 20 to 32 kHz, no guard bands → shift to **20-24, 24-28, 28-32 kHz** and combine; receiver: bandpass filter each band and shift back to 0-4 kHz.
- **WDM**: an analog multiplexing technique to combine optical signals; a single line on fibre wastes the bandwidth. Same idea as FDM (combines signals of different frequencies); difference: optical signals on fibre, very high frequencies, prism. $\lambda_1 + \lambda_2 + \lambda_3$ on one fibre.
- **TDM**: a digital multiplexing technique that allows several digital signals to share the high bandwidth of a link in time; combines several low-rate channels into a high-rate one. Analog input: sample, change to digital data, then multiplex.
- **Unit** = 1 bit, one character, or one block of data. A round of units from each input = a **frame** of n **time slots**. Input unit duration $T$ → slot $T/n$, frame $T$. Link **n times faster**, unit **n times shorter**. The frame rate is always the same as any input rate. The data rate of the output link must be n times the data rate of a connection.
- Slide figure: four inputs at 1 Mbps (bit duration 1 μs) → link 4 Mbps, bit duration 0.25 μs, 1 000 000 frames/s; the first frame is 0101 (each line's first bit, line 4 down to line 1). In the lines A, B, C figure, Frame 1 = C1 B1 A1.
- Synchronous TDM is **not efficient**: a source with nothing to send leaves its slot **empty**. **Statistical TDM** improves efficiency by removing the empty slots.

| Strategy | Trigger | Slide figure | Output |
|---|---|---|---|
| **Multilevel multiplexing** | the data rate of an input line is a multiple of others | 20 + 20 → 40 kbps, then 4 × 40 | 160 kbps |
| **Multiple-slot allocation** | an input has multiple rates of the others → more than one slot in a frame | 50 kbps → DEMUX → 2 × 25; 5 × 25, two slots per frame for the 50 kbps input | 125 kbps |
| **Pulse stuffing** (bit padding, bit stuffing) | bit rates are not integer multiples of each other | highest rate is the **dominant** rate; dummy bits raise 46 → 50; 3 × 50 | 150 kbps |

- Three strategies or a combination. Slide 42 writes "50-kHz data rate"; it means 50 kbps.
- **Synchronization** between MUX and DEMUX is a major issue. **Framing bits**: one or more synchronization bits usually added to the **beginning** of each frame, following a pattern (1 0 1 …) frame to frame so the demultiplexer can separate the time slots accurately.

**Formulas** (FDM from Example 1, TDM from Example 2)

$$B_{link} = n \times B_{channel} + (n - 1) \times G$$

$$\text{frame rate} = \frac{\text{input bit rate}}{\text{bits per unit}} = \text{input unit rate} \qquad \text{frame duration} = \frac{1}{\text{frame rate}} = T$$

$$\text{link bit rate} = n \times \text{input bit rate} \qquad \text{slot} = \frac{T}{n} \qquad \text{bit duration} = \frac{1}{\text{link bit rate}} \qquad \text{bits per frame} = n \times \text{bits per unit}\ (+\ \text{framing bits})$$

$$\text{link bit rate} = \text{frame rate} \times \text{bits per frame} \quad \text{(the framing bit counts: E06 2, } 250 \times 33 = 8250\ \text{bps)}$$

| Worked number | Result |
|---|---|
| Example 1: 5 channels × 100 kHz, 10 kHz guard bands | 4 guard bands; $(5 \times 100) + (4 \times 10) = 540$ kHz |
| Example 2: four 100-kbps channels, 2-bit slot, frame rate | $100\ \text{kbps} / 2 = 50\,000$ frames/s |
| Example 2, frame duration | $1 / 50\,000 = 20$ μs |
| Example 2, bit rate of the shared channel | $4 \times 100 = 400$ kbps |
| Example 2, bit duration | $1 / 400\ \text{kbps} = 2.5$ μs; frame = 8 bits = 8 × 2.5 μs |
| Slide figure: 4 × 1 Mbps, 1-bit slots | 4 Mbps, 0.25 μs, 1 000 000 frames/s |
| E06 2: 4 × 250 chars/s, 8-bit chars, 1 framing bit | 2 kbps per source, 250 frames/s, 4 ms, 33 bits, 8250 bps |
| E06 3: 100 + 200 kbps, multiple-slot | 1 + 2 slots, 100 000 frames/s, 10 μs, 300 kbps |

Units: Hz for a bandwidth, bps for a bit rate, frames/s for a frame rate, s for a duration.

## Lecture 06b: the data-link layer

- The Internet: networks glued together by connecting devices (routers or switches). **Nodes** = hosts and routers; **links** = LANs and point-to-point networks. The data-link layer is active at **every hop** (Alice → R2 → R4 → R5 → R7 → Bob); a router has network, data-link and physical layers.
- **A packet at the data-link layer is called a frame.** Encapsulation and decapsulation at each intermediate node for two reasons: 1. each link may use a **different protocol with a different frame format**; 2. even with the same protocol, the **link-layer addresses are normally different**.
- Position: between the physical layer and the network layer; provides services to the network layer, receives services from the physical layer.
- Four services: 1. **Framing**, encapsulating the datagram in a frame before sending it to the next node. 2. **Flow control**, controlling the rate of producing frames w.r.t. the rate of consumed frames. 3. **Error control**, error detection and correction. 4. **Congestion control**.
- Two sublayers: **DLC** (Data Link Control), issues common to both point-to-point (dedicated) and broadcast (shared) links: framing, flow control, error control. **MAC** (Media Access Control), only issues specific to broadcast (shared) links.
- Why link-layer addresses: the IP addresses in the datagram define the two ends but **cannot define which links** the datagram passes through. Two data-link addresses are added to the frame header and **changed every time the frame moves from one link to another**.
- **Link-layer address = physical address = MAC address.** Ethernet: **48 bits (6 bytes)**, **12 hexadecimal digits separated by colons** (00:1A:3F:F1:4C:C6). First 3 bytes = Organizationally Unique Identifier (F0:1F:C7 → Apple; a block of $2^{24}$ addresses).
- **Link-layer switch**: two layers only, data-link and physical; sends data only to the single device it is intended for; most are **layer 2** (layer 3 switches less common).
- **Order of addresses: IP source-destination; link-layer destination-source.** Small internet, Alice (N₁ L₁) to Bob (N₈ L₈): Link 1 **[L₂ | L₁ | N₁ | N₈]**, Link 2 **[L₅ | L₄ | N₁ | N₈]**, Link 3 **[L₈ | L₇ | N₁ | N₈]**; N₁ N₈ never change.
- **ARP**: one of the auxiliary protocols defined in the **network layer**; maps an IP address to a link-layer address; runs all the time in the background (a host does not know when a request will come). **Request is broadcast**: "Looking for link-layer address of a node with IP address N₂". **Reply is unicast**: "I am the node and my link-layer address is L₂".

| ARP packet field | Request (A asks for N₂) | Reply (B answers) |
|---|---|---|
| Hardware type (16 bits) | 0x0001 Ethernet | 0x0001 |
| Protocol type (16 bits) | 0x0800 IPv4 | 0x0800 |
| Hardware length, protocol length (8 + 8 bits) | 0x06 (6-byte MAC), 0x04 (4-byte IP) | 0x06, 0x04 |
| Operation (16 bits) | 0x0001 = request | 0x0002 = reply |
| Source hardware, source protocol | L₁, N₁ | L₂, N₂ |
| Destination hardware, destination protocol | **All 0s** (empty in request), N₂ | L₁, N₁ |
| Carrying frame | destination BA (broadcast address), source A | destination A, source B |

- Alice to Bob, three nodes away; Alice knows N_B, N_A, L_A. At each node: network layer → **forwarding table** gives the next-hop IP → **ARP** gives its MAC → data-link layer builds the frame → physical layer sends the signal. Routers decapsulate and re-encapsulate.

| Node | Forwarding table: N_B → | ARP asks, who replies | Frame sent (L dest · L src · N src · N dest) |
|---|---|---|---|
| Alice | N₁ | ARP (Alice) asks N₁, ARP (R1) replies L₁ | L₁ · L_A · N_A · N_B · Data |
| R1 | N₃ | ARP (R1) asks N₃, ARP (R2) replies L₃ | L₃ · L₂ · N_A · N_B · Data |
| R2 | N_B (directly connected) | ARP (R2) asks N_B, ARP (Bob) replies L_B | L_B · L₄ · N_A · N_B · Data |

- **N_A and N_B have not been changed during the whole journey.** The source L is always the sender's own interface on that link (R1 sends from L₂, not L₁).
- Summary: creation and delivery of a frame to another node along the link; packetizing (framing); flow control and error control along the link; controlling access to the link; link-layer addressing; ARP to map IP addresses to MAC addresses.
