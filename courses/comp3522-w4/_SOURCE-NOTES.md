## Deck 1: abstract classes
- Java `public abstract class AbstractClass {}` / `class ConcreteClass extends AbstractClass`.
- C++ abstract classes: cannot be instantiated (just like Java); used to define an implementation or a base class; intended to be extended; implemented as a class that has **one or more pure virtual functions**.
- `class AbstractClass { public: virtual void AbstractMemberFunction( ) = 0; // PURE SPECIFIER  virtual void NonAbstractMemberFunction1( ); void NonAbstractMemberFunction2( ); int x; };` `class ConcreteClass : public AbstractClass { public: void AbstractMemberFunction( ) override { } void NonAbstractMemberFunction1( ) override { } };`
- Pure specifier: a pure virtual function MUST be overridden by a concrete derived class; a declaration cannot have both a pure specifier and a definition: `virtual void g() { } = 0; // ERROR!`.
- Rules: cannot use an abstract class as a function return type or a parameter type: `A functionA(); // WRONG`, `void functionB(A aParam); // WRONG`. Can use pointers and references: `A* pa; // OK`, `A& functionA(A& aParam); // OK`.
- Virtual members are inherited: a class derived from an abstract class is abstract unless we override **each** pure virtual function (just like Java); we can derive an abstract class from a non-abstract class; CAUTION: calling (directly or indirectly) a pure virtual function from an abstract class constructor is UNDEFINED. See oop_abstract.cpp and oop_virtual.cpp.
- oop_abstract/main.cpp: `class creature { public: virtual void all_info() const = 0; }; class person : public creature { person() = default; person(const std::string& name) : name(name) {} set_name, get_name const, void all_info() const override { cout << "My name is " << name << endl; } protected: std::string name; };` main: `//creature some_beast; // Error: abstract class  creature* hulk = new person("Dr Bruce Banner"); hulk->all_info();` → `My name is Dr Bruce Banner` (never deleted: leak, and creature has no virtual destructor). oop_virtual/main.cpp is identical plus `int age = 0;` in creature (an abstract class can have data members).

## Deck 1: interfaces
- Java `public interface Animal {}` / `class Dog implements Animal`.
- C++ interfaces: describe behaviour without committing to an implementation; no implementation; specifies a polymorphic interface; **virtual destructor** to ensure that when an instance of an implementing class is deleted polymorphically the correct derived destructor is called; pure virtual functions, no other kinds of functions (+ a regular virtual destructor).
- `class Animal { public: virtual ~Animal( ) {} //regular virtual destructor  virtual void move_x(int x) = 0; virtual void move_y(int y) = 0; virtual void eat( ) = 0; }`.
- Abstract class vs interface: abstract class defines an implementation to be extended by concrete classes; enforces a contract between designer and users; at least one pure virtual function; can have data members and virtual and non-virtual member functions. An interface is a "pure abstract class": purely virtual functions, no data.
- Table (not implemented → fully implemented): **Interface**: only pure virtual functions, virtual destructor, no data members, can NOT be instantiated. **Abstract class**: at least 1 pure virtual function, virtual destructor, has functions and data members, can NOT be instantiated. **Concrete class**: no pure virtual functions, virtual destructor if a base class that has children, has functions and data members, CAN be instantiated.

## Deck 2: friends
- A friend declaration grants a function (or another class) access to private and protected members; the declaration appears in the class body; the definition appears outside the class body.
- `class Dollar { private: int num; friend Dollar sum(const Dollar &d1, const Dollar &d2); public: Dollar(int d) : num(d){}; }` and in main.cpp `Dollar sum(const Dollar &d1, const Dollar &d2) { return Dollar(d1.num + d2.num); }` with `Dollar d1{5}; Dollar d2{7}; Dollar dollarSum = sum(d1,d2);`. Shipped Dollar.hpp comment: "friend function unaffected by visibility, not a member function"; Dollar.cpp: "dollar cpp empty. friend sum function doesn't have to be implemented here"; main.cpp: "this implementation can be anywhere. Does NOT belong to Dollar class"; adds `int GetNum(){return num;}` and prints `dollarSum.GetNum()` → **12**.
- Friend classes: `class Spy; //forward declaration  class Boss { friend class Spy; int pin; //private  public: Boss(int p) : pin(p){} }; class Spy { int pin; public: Spy(int p) : pin(p){} void print(Boss b) { cout << b.pin; } };` main `Boss boss{1111}; Spy spy{2222}; spy.print(boss);` → 1111. Shipped FriendClass adds `void Boss::print(Spy *s) { cout << "Boss using Spy's pin: " << s->pin; }` with comment "Spy did not make boss their friend, so can't access PIN" — as shipped this **does not compile** (`'int Spy::pin' is private within this context`); `//friend class Boss;` in Spy is the commented fix; `//cout << boss.pin; //can't access boss' pin from main`.
- Friendship is **not transitive** (A < B and B < C means A < C is transitive; Boss friend Spy, Spy friend Minion does NOT make Boss friend Minion), **not inherited**, and **access specifiers have no effect** (friends can be declared in the private, protected or public section).

## Deck 2: operator overloading
- Customize C++ operators for operands of user-defined types; 38 overloadable: `+ - * / % ^ & | ~ ! = < > += -= *= /= %= ^= &= |= << >> >>= <<= == != <= >= && || ++ -- , ->* -> () []` ("No, you don't have to memorize this list").
- Basic rules: adhere to the operator's commonly known semantics; if you provide one of a set, provide them all (overload + → overload +=; prefix ++ → postfix ++); when the meaning is not obviously clear, don't overload.
- Operators are overloaded as functions with special names: `operator+=()`, `operator-=()`, `operator<=()`. Implemented as a **member function of the left operand's type** (unary operators; `objA += 10`, `objA -= objB`, `objA++`) or as a **friendly non-member function** (`objA <= 10`, `objA < objB`); a non-member that must access private members must be a friend.
- Canonical insertion operator (most commonly overloaded; friendly non-member): `friend std::ostream& operator<<(std::ostream& os, const T& obj) { os << obj.myString; return os; }`. Date example: `class Date { int mo, da, yr; public: Date(int m, int d, int y) { mo = m; da = d; yr = y; } friend ostream& operator<<(ostream& os, const Date& dt); }; ostream& operator<<(ostream& os, const Date& dt) { os << dt.mo << '/' << dt.da << '/' << dt.yr; return os; }` main `Date dt(5, 6, 92); cout << dt; // 5/6/92  cout << 77; // 77`. "What looks easier? `cout << myObject.getInfo();` OR `cout << myObject;`"
- Canonical extraction: `friend std::istream& operator>>(std::istream& is, T& obj) { is >> obj.myVar; return is; }`; Date: `istream& operator>>(istream &input, Date &dt) { input >> dt.mo >> dt.da >> dt.yr; return input; }`, used as `Date dt(0, 0, 0); cin >> dt;`; may also be defined inline inside the class after `friend`.
- Comparison operators: friendly non-members; the standard library's algorithms and types always expect `operator<`; define six: `==`, `!=`, `<`, `>`, `<=`, `>=`. 1. `friend bool operator==(const X& lhs, const X& rhs) { /* actual comparison */ }`; 2. `operator!=` → `return !operator==(lhs,rhs); //or !(lhs == rhs)`; 3. `operator<` actual comparison; 4. `operator>` → `return operator<(rhs,lhs); //or rhs < lhs`; 5. `operator<=` ("lhs is not greater than rhs") → `return !operator>(lhs,rhs);`; 6. `operator>=` ("lhs is not less than rhs") → `return !operator<(lhs,rhs);`.
- Unary ++/--: prefix and postfix forms; **postfix accepts a dummy (unused) int argument** so they can be told apart; overload both; member functions. `Counter& operator++() { // Prefix: ++counter  do actual increment; return *this; }`, `Counter operator++(int) { // Postfix: counter++  Counter tmp(*this); //copy original value  operator++(); //internal increment  return tmp; //return non incremented original value }`. Postfix is defined in terms of prefix, performs an extra copy, slightly slower: hence `for (int i = 0; i < upperBound; ++i)`.
- Binary arithmetic: overload + → overload +=; `operator+` doesn't change the left argument → friendly non-member; `operator+=` changes it → member; `operator+` is defined in terms of `+=`. `Fraction& operator+=(const Fraction& rhs) { /* add rhs to *this */ return *this; }`; `friend Fraction operator+(Fraction lhs, const Fraction& rhs) { lhs += rhs; return lhs; }` — `Fraction z = x + y;` with x 5.5, y 1.1: lhs is a **copy** that becomes 6.6 and is returned. Notes: `operator+=` returns by reference, `operator+` returns a copy, because `a + b` is expected to be a new value; `operator+` takes the left parameter by copy.
- Member or non-member? 1. unary (++, --, ()) → member; 2. binary that treats both operands equally / leaves them unchanged (+, -, <, >) → non-member; 3. binary that does NOT treat both equally (+=, -=) → member of the left operand's type. Table: unary (!, ~, ++, --) member "operates on a single object (self)"; assignment (=, +=, -=) member "modifies the left-hand object"; comparison (==, !=, <, >) non-member (friend) "symmetric comparison"; arithmetic (+, -, *, /) non-member (friend) "flexibility for non-class types (e.g. int + MyClass)"; stream (<<, >>) non-member (friend) "needs to work with std::ostream / std::istream" (table credited to chatgpt.com).
- operators/Character.hpp: `class Character { char c; public: Character() {c = ' ';} Character(char c) : c(c){cout << "constructing char: " << c << endl;} Character(const Character& other) : c(other.c) {} ~Character() {} Character& operator=(Character rhs) { mySwap(*this, rhs); return *this; } void mySwap(Character &original, Character &other) { std::swap(original.c, other.c); } Character& operator++() { c += 1; return *this; } Character operator++(int){ Character tmp(*this); operator++(); return tmp; } Character& operator+=(const Character& rhs) { c += rhs.c; return *this; } private: friend Character operator+(Character lhs, const Character &rhs); friend bool operator== (…) { return lhs.c == rhs.c; } operator!= { return !operator==(lhs,rhs); } operator< { return lhs.c < rhs.c; } operator> { return operator<(rhs,lhs); } operator<= { return !operator>(lhs, rhs); } operator>= { return !operator<(lhs,rhs); } friend ostream& operator<<(ostream &os, const Character& character) { os << "Character: " << character.c << endl; return os; } };` main.cpp defines `Character operator+(Character lhs, const Character &rhs) { lhs += rhs; return lhs; }` outside the class (the friend declaration sits in the **private** section: access specifiers have no effect on friends). main: `Character char1('A'); Character char2('B'); cout << boolalpha << endl; cout << "char1 less than char2?: " << (char1 < char2) << endl << endl;` → `true`; printing both → `Character: A`, `Character: B`; `char1++;` → `Character: B`; `Character char3 = '!';` → `constructing char: !` (implicit conversion through the char constructor); `char1 += char3; //char1.operator+=(char3);` → 'B' (66) + '!' ## Deck 2: copy assignment operator (=)
- `MyClass A; MyClass B; B = A; //A contents copied to B` (picture: B's contents replaced by A's).
- Canonical form uses the **copy-and-swap idiom**; it is a member function: `MyClass& MyClass::operator=(MyClass rhs) { mySwap(*this, rhs); return *this; }`.
- Copy and swap avoids code duplication: 1. use the copy constructor to create a local copy of the original object; 2. acquire the copied data with a swap function, swapping old data with new; 3. the temporary local copy is destroyed, taking the old data and leaving the new data in the destination.
- Needs: 1. a working copy constructor; 2. a working destructor; 3. a swap function that does not throw and swaps all data members. Don't use std::swap on the ENTIRE object: it uses the copy constructor and the copy assignment operator → recursive spiral.
- Example class: `class Example { size_t list_size; int * my_list; public: Example(size_t size = 0) : list_size{size}, my_list{size ? new int[size] : nullptr} {} Example(const Example& other) : list_size{other.size}, my_list{size ? new int[size] : nullptr} { // A loop here to copy the data… } ~Example() { delete[] my_list; } void mySwap(Example& first, Example& second) { using std::swap; swap(first.size, second.size); swap(first.my_list, second.my_list); } Example& operator=(Example other) { mySwap(*this, other); return *this; } };` (slides mix `size`/`list_size`). Walkthrough of `B = A;`: pass by value uses the copy constructor to create a copy named `other` holding A's contents; mySwap exchanges other's and B's contents (B now has A's contents, other has B's old contents); other's destructor is invoked when leaving function scope, freeing B's old data. "Think of assignment as replacing the object's old state with a copy of some other object's state."
