HTML (L1)

  • <!DOCTYPE html> = HTML5; <html> root, <head> meta info, <body> visible. HTML creates elements; DOM (tree) = how they attach; CSS = where/how they look; JS = interactivity.
  • Single (empty) tags <img> <br> <hr>. Global attributes style id class: id unique per page, class need not be.
  • Block: div h1–h6 p form header footer section. Inline: span a img. <strong>/<em> semantic importance; <b>/<i> none.
  • Radio buttons with the same name = one group. URL, 4 parts: protocol, domain name, folder path, file name; no file name → index.html.

JSON (L2 s26–29)

An object has methods, prototypes, references: serialize it to send. JSON.stringify(obj) object → string (serialize); JSON.parse(str) string → object (deserialize). JSON.stringify({name: "John", age: 22}) → '{"name":"John","age":22}', typeof "string".

Web Storage (L2 s30–44, L3 s7)

  • localStorage: no expiration date. sessionStorage: one session, lost when the browser tab closes.
  • Per origin (protocol + domain + port; path does not matter; subdomain = other origin): "same origin, same browser, same machine". About 5 MB.
  • Strings only: getItem → string or null. setItem(k, v) getItem(k) removeItem(k) clear(). Object: setItem("user", JSON.stringify(o)) / JSON.parse(localStorage.getItem("user")).

Architecture (L2 s4–22)

  • "Architecture is not code. It is the decisions you make before you write code." Order: Monolithic → Layered → Microservices.
  • Monolithic: all logic in one deployable unit, one machine, one stack. Add a feature: 1 shut down entire app, 2 add it, 3 (may need to) recompile everything. Good for MVPs; hard to scale.
  • Microservices: "a collection of loosely coupled, independently deployable services". Pros: fix one without shutting all down; one function → separate teams; own machine/stack. Cons: many API calls → complexity; orchestration, monitoring.
  • Reliability = works under normal conditions · Robustness = handles bad input (invalid JSON → 400 Bad Request) · Resilience = survives, recovers (store sells without recommendations).
  • SOA ≈ MSA "in this course". Course: a simplified, API-centric MSA; API calls follow REST; client and servers on different origins; responses often JSON. Products mix patterns (Netflix); others: Event-Driven, Serverless, MVC, MVVM, Hexagonal, CQRS.

Node.js (L4)

  • Open-source JS runtime on Chrome V8, outside the browser. "Single-threaded, non-blocking, asynchronous" [real: event loop; thread pool for file I/O].
  • PHP, 4 steps: send task → wait while file read → return content → ready for next. Node, 3: send task → ready for next → return content when read.
  • Restaurant: Ex 1 one waiter for all = single-threaded non-blocking (JS); Ex 2 waits at kitchen = single-threaded blocking; Ex 3 = multi-threaded (100 requests → 100 threads).
  • Modules: exports.area = function (r) {…}; then const mo = require('./modules/math'); (./ same folder, .js optional). Built-in http url fs; mysql needs npm install.
const http = require('http');
const url = require('url');
const fs = require('fs');
http.createServer(function (req, res) {
  const q = url.parse(req.url, true);   // ?name=John → q.query.name
  fs.readFile("." + q.pathname, function (err, data) {
    if (err) {
      res.writeHead(404, {'Content-Type': 'text/html'});
      return res.end(q.pathname + " 404 Not Found!");
    }
    res.writeHead(200, {'Content-Type': 'text/html',
                        'Access-Control-Allow-Origin': '*'});
    res.write(data);
    return res.end();
  });
}).listen(8888);           // try http://localhost:8888/file.txt

url.parse('http://localhost:8888/default.htm?name=John&age=23', true): host 'localhost:8888' · pathname '/default.htm' · search '?name=John&age=23' · query {name: 'John', age: '23'}. Status: 200 OK · 3xx redirect · 4xx client (403 Forbidden, 404 Not Found) · 5xx server.

CORS (L5 s15–21)

  • "CORS is a security feature implemented in web browsers and is configured by the contacted server in the response's header." Default: Same-Origin Policy; browsers block cross-origin requests unless the server explicitly allows it.
  • Origin = domain + protocol + port (80 HTTP, 443 HTTPS). "Access-Control-Allow-Origin": "*" in writeHead = all origins; also -Allow-Methods, -Allow-Headers.
  • Preflight = method OPTIONS, sent first by the browser (e.g. for application/json; not for form-urlencoded). Postman ignores CORS; address-bar GETs need no header; CORS is not encryption.

Promises (L6)

  • Executor runs immediately on new Promise(...) (eager). resolve/reject change state synchronously; handlers run asynchronously, mutually exclusive, only once; the first call wins, later ones are ignored.
  • Promise.resolve().then(() => console.log(1)); console.log(2); → 2 1 (handlers never run synchronously).
  • Order: sync lines (incl. executor) → microtasks (handlers, in the order queued) → timers.
console.log("7");
let p = new Promise(function (resolve, reject) {
  resolve("4"); console.log("2"); reject("3"); console.log("5");
});
console.log("1");
p.then(m => console.log(m), e => console.log(e));
console.log("8");                  // 7 2 5 1 8 4   ("3" never)

new Promise(resolve => resolve(1))
  .then(a => { console.log("First:", a);  return a * 2; })
  .then(b => { console.log("Second:", b); return b * 3; })
  .then(c => console.log("Final:", c));
// First: 1   Second: 2   Final: 6
  • .then(onSuccess, onFailure) returns a new promise (chaining). Return a value = resolve the next; throw = reject the next.
  • .catch(f) = .then(null, f). .finally(f) ≈ .then(f, f): runs either way, no argument, passes the value/error on, does not handle the rejection.
  • No handler → console Uncaught (in promise) …. Old Chrome shows status "resolved" [real: "fulfilled"].
  • async function automatically returns a promise; await (inside async) waits for a promise to resolve or reject.

Node to MySQL and CRUD (L5 s31–45, L7)

const mysql = require("mysql");      // npm install mysql
const con = mysql.createConnection({ host: "localhost",
  user: "root", password: "", database: "webdev" });
con.connect(function (err) {
  if (err) throw err;
  let sql = "INSERT INTO score(name, score) " +
            "values ('elon musk', 2900)";
  con.query(sql, function (err, result) {
    if (err) throw err;
    console.log("1 record inserted");
  });
});
  • Create a mysql object → connect → run a SQL statement. Credentials stay on the server; least privilege (a SELECT-only user).
  • CRUD = Create (table/DB), Read, Update (records), Delete (record, or drop a table). A database is not a DBMS.
  • Primary key unique per row; foreign key = primary key of another table in this one. 1:M patient → visits; M:M via an associative table. Referential integrity: deleting a patient orphans its visits.
