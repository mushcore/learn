---
title: External, internal and software interrupts
minutes: 10
---

A system call stops the running program and hands control to the kernel, which is what an interrupt does. Slide 1 sorts interrupts into three classes, and a system call belongs to exactly one of them.

## Three classes of interrupt (slide 1)

| | External interrupts (hardware interrupts) | Internal interrupts (exceptions) | Software interrupts (traps) |
|---|---|---|---|
| Timing | **Asynchronous** | **Synchronous** | **Synchronous** |
| Description | | *Generated by CPU itself whenever some unusual condition occurs* | |
| Examples | *Moving mouse, or pressing a key on the keyboard* | *1/0* | *System calls* |

Each class has two names, and both are fair game: an external interrupt is a **hardware interrupt**, an internal interrupt is an **exception**, and a software interrupt is a **trap**.

## Asynchronous means unrelated to the instruction running

An **external** interrupt comes from a device outside the CPU. The mouse moves or a key goes down whenever the user decides, so the interrupt can land between any two instructions of the running program. That is what asynchronous means here: its timing has nothing to do with the code being executed.

The other two classes are **synchronous**: an instruction in the running program causes them, so they happen at the same point every time the program runs with the same input.

- An **internal** interrupt is the CPU reacting to its own instruction going wrong. The slide's example is *1/0*, one divided by zero: the divide instruction cannot produce a result, so the CPU raises an exception.
- A **software** interrupt is raised on purpose. The program executes an instruction whose whole job is to interrupt itself and enter the kernel. That instruction is how every system call reaches the operating system.

:::quiz 1/0 is not I/O
The slide's internal-interrupt example is *1/0*, one divided by zero. The deck's text layer reads it as "I/O". A device finishing an I/O operation signals the CPU from outside, which is an external interrupt, not an exception.
:::

## A system call is a software interrupt

The program asks for the kernel's help by executing a trap instruction. On 32-bit x86 Linux that instruction is `int 0x80` ([x86 registers and int 80h](#/comp4736-p5/registers-and-int80)), and in Tanenbaum's eleven steps it is step 6, the *TRAP instruction* ([the eleven steps](#/comp4736-p5/eleven-steps)). Because the program itself executes that instruction at a known point, a system call is synchronous.
