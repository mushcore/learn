## Interrupt classes and the standard streams

| | External interrupts (hardware interrupts) | Internal interrupts (exceptions) | Software interrupts (traps) |
|---|---|---|---|
| Timing | Asynchronous | Synchronous | Synchronous |
| Example | Moving mouse, pressing a key | 1/0 (generated by the CPU itself) | System calls |

| Stream | Symbol | fd | Source or target |
|---|---|---|---|
| stdin | `<` | 0 | keyboard or file |
| stdout | `1>` (or `>`) | 1 | terminal or file |
| stderr | `2>` | 2 | terminal or file |

`read` returns the byte count including the newline: `Hello World` + Enter = 12 bytes (slide 9; slide 7 prints 13). Manual section 2 is system calls; an OS provides a procedure library because system calls are machine dependent and often written in assembly.

## The x86 convention

| | 32-bit x86 (i386) | x86-64 |
|---|---|---|
| Call number | EAX | rax |
| Arguments | ebx, ecx, edx, esi, edi, ebp | rdi, rsi, rdx, r10, r8, r9 |
| Enter the kernel | `int 0x80` (80h) | `syscall` |
| Result | EAX | rax |
| read, write, open, close | 3, 4, 5, 6 | 0, 1, 2, 3 |

sys_exit is 1 on 32-bit x86. MIPS: service in `$v0` (15 = write to file), arguments `$a0`, `$a1`, `$a2`, then `syscall`.

## The eleven steps of read(fd, buffer, nbytes)

| Step | Who | What |
|---|---|---|
| 1, 2, 3 | user program | push nbytes, &buffer, fd (reverse order) |
| 4 | user program | call the library procedure read |
| 5 | library procedure | put the system-call number in a register |
| 6 | library procedure | TRAP: user mode to kernel mode, fixed address in the kernel |
| 7 | kernel | dispatch through the table of handler pointers, indexed on call number |
| 8 | kernel | the system-call handler runs |
| 9 | kernel to library | return to the instruction following the TRAP |
| 10 | library procedure | return to the user program |
| 11 | user program | clean up the stack (increment SP) |

## fork, execve and the shell

| fork returns | Meaning |
|---|---|
| −1 | fork fails |
| 0 | in the child process |
| > 0 | in the parent: the child's process ID |

Both processes continue at the instruction following the fork. A successful execve does not return (the program is replaced); code after it runs only if it fails. The shell: parent `waitpid(−1, &status, 0)`, child `execve(command, parameters, 0)`.

## Links and mount

| | Hard link | Symbolic link |
|---|---|---|
| Inode | same as the original | its own |
| Holds | the file's data, shared | the name of the original (Size 7 for my_file) |
| Original deleted | still reads; Links 2 → 1 | No such file or directory |

`link("/usr/jim/memo", "/usr/ast/note")` gives note the i-number 70. mount merges two file systems into one.

## Blocking, non-blocking and asynchronous I/O

| Mode | Behaviour | How |
|---|---|---|
| Blocking (the default for most I/O calls) | suspends the process until the operation completes | `open("file.txt", O_RDONLY)` |
| Non-blocking | returns immediately; the program checks back later | `fcntl(fd, F_SETFL, O_NONBLOCK)` or `O_RDONLY \| O_NONBLOCK` (no effect on regular files and block devices) |
| POSIX AIO | starts the operation, which completes in the background | `struct aiocb` + `aio_read(&cb)`; also aio_write, aio_error, aio_return, aio_fsync |

Blocking: simpler code flow. Non-blocking: stays responsive (GUIs, network servers) at the cost of more complex logic.
